# GMP 바이오공정 문제집

GMP·바이오공정 강의 복습용 **객관식(5지선다) 문제집 웹 앱**입니다.
태블릿·PC·휴대폰 브라우저에서 바로 쓸 수 있고, 빌드 도구 없이 HTML·CSS·JavaScript만으로 만들어져 GitHub Pages에 그대로 올리면 됩니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| **단원별 학습** | 범위(복수 선택)와 문제 수를 고르고, 답을 고르면 즉시 정답/오답·해설·**보기별 해설**·**PDF 출처**를 보여 줍니다. |
| **단원별 시험** | 시험지 형식으로 끝까지 푼 뒤 한꺼번에 채점하고, 문제별 정답과 해설 목록(ANSWER KEY & EXPLANATIONS)을 보여 줍니다. |
| **전범위 모의고사** | 모든 단원에서 문항 수에 비례해 고르게 출제되는 실전 시험지입니다(제한 시간: 문항당 2분, 인쇄 가능). |
| **미출제 우선 출제** | 한 번도 안 푼 문항 → 오답 노트 문항 → 오래전에 푼 문항 순으로 출제해, 매 시험지에 미출제 문항이 포함됩니다. 시험지 머리말에 미출제 문항 수가 표시됩니다. |
| **무작위 섞기** | 문제 순서와 보기 순서를 섞습니다. 섞어도 정답 판정·보기별 해설 번호가 정확히 따라갑니다. |
| **오답 노트** | 틀린 문제(시험 모드의 미응답 포함)를 저장하고 「오답만 다시 풀기」로 복습합니다. 다시 맞히면 오답 노트에서 빠집니다. |
| **기록** | 회차별 점수와 주차(단원)별 정답률을 저장해 결과 화면과 「기록」 화면에 보여 줍니다. |
| **진행 표시** | 진행 바와 「몇 번 / 전체」를 항상 위에 표시합니다. 시험 중 새로고침해도 「이어서 풀기」로 돌아올 수 있습니다. |
| **화면** | 한국어 UI, 모바일 우선 레이아웃, 큰 터치 버튼, 다크 모드(자동/라이트/다크), PC에서는 2단 시험지. |

기록은 **이 기기의 이 브라우저(localStorage)에만** 저장됩니다. 휴대폰과 PC의 기록은 서로 공유되지 않습니다.

## GitHub Pages 켜는 방법

1. 이 저장소의 변경 사항이 공개할 브랜치(보통 `main`)에 들어가 있는지 확인합니다.
   (작업 브랜치에만 있다면 먼저 Pull Request를 만들어 `main`에 병합하세요.)
2. GitHub 저장소 페이지에서 **Settings → Pages** 로 이동합니다.
3. **Build and deployment → Source** 를 **Deploy from a branch** 로 선택합니다.
4. **Branch** 를 `main`, 폴더를 `/ (root)` 로 고르고 **Save** 를 누릅니다.
5. 1~2분 뒤 같은 화면 위쪽에 사이트 주소가 나타납니다.
   보통 `https://<깃허브 아이디>.github.io/<저장소 이름>/` 형태이며, 이 저장소라면
   `https://jsm012003-sketch.github.io/GMP-Quiz/` 입니다.
6. 휴대폰·태블릿에서는 그 주소를 열고 브라우저 메뉴의 **홈 화면에 추가**를 누르면 앱처럼 쓸 수 있습니다.

> 참고: 비공개(private) 저장소는 GitHub 무료 플랜에서 Pages를 켤 수 없습니다. 저장소를 공개로 바꾸거나 유료 플랜이 필요합니다.
> 문제 파일을 고친 뒤 바로 반영되지 않으면 1~2분 기다렸다가 새로고침하세요.

### 내 컴퓨터에서 미리 보기

`index.html`을 더블클릭으로 열면(file://) 브라우저 보안 정책 때문에 문제 파일을 읽지 못합니다. 폴더에서 간단한 서버를 띄워 여세요.

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

## 문제 파일 추가 방법

문제는 `questions/` 폴더의 JSON 파일에 있고, **`questions/index.json` 목록에 파일명만 적으면** 자동으로 범위 선택에 나타납니다.

1. `questions/` 폴더에 새 파일을 만듭니다. 예: `questions/wk03.json`
2. 아래 형식으로 문항을 적습니다.
3. `questions/index.json` 목록에 파일명을 추가합니다.

   ```json
   ["ot.json", "wk02.json", "wk03.json", "gmp01.json", "gmp02.json", "gmp03.json", "integrated.json"]
   ```

4. (권장) 형식 검사기를 실행합니다. 오류가 있으면 어떤 파일 몇 번째 문항인지 알려 줍니다.

   ```bash
   python3 tools/validate_questions.py
   ```

5. 커밋하고 푸시하면 GitHub Pages에 반영됩니다.

### 문제 JSON 형식

```json
{
  "week": "WK03",
  "title": "Upstream Process 2",
  "questions": [
    {
      "id": "wk03-001",
      "type": "상황판단",
      "question": "문제 본문",
      "box": ["ㄱ. (선택) <보기> 진술", "ㄴ. ...", "ㄷ. ..."],
      "choices": ["보기1", "보기2", "보기3", "보기4", "보기5"],
      "answer": 2,
      "explanation": "해설. **굵게** 표시 가능",
      "choiceNotes": ["보기1이 맞거나 틀린 이유", "…", "…", "…", "…"],
      "source": "WK03 Upstream Process 2 PDF p.12–14, 강의 01:32"
    }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `week` | ✔ | 단원 이름(범위 선택·통계의 기준). 같은 `week`를 쓴 파일은 한 단원으로 합쳐집니다. |
| `title` | ✔ | 단원 제목 |
| `id` | ✔ | 전체 파일에서 겹치지 않는 고유 번호. **한 번 정한 id는 바꾸지 마세요**(기록·오답 노트가 id로 연결됩니다). |
| `type` |  | `상황판단` · `계산` · `연결` · `개념` 중 하나 |
| `question` | ✔ | 문제 본문 |
| `box` |  | `<보기>` 상자에 들어갈 진술 목록(「있는 대로 고른 것은?」 유형) |
| `choices` | ✔ | 보기 배열(2~10개, 기본 5지선다) |
| `answer` | ✔ | 정답 번호, **1부터 시작** |
| `explanation` |  | 해설. `**굵게**`와 줄바꿈 사용 가능. 보기를 섞으므로 ①② 같은 보기 번호는 쓰지 마세요. |
| `choiceNotes` |  | 보기별 해설(보기와 같은 순서·같은 개수). 화면에서는 섞인 번호에 맞춰 표시됩니다. |
| `source` |  | 출처. `p.`는 **PDF 뷰어의 쪽 번호**입니다(슬라이드 하단 'Page / N'과 1~2쪽 차이 날 수 있음). 강의 녹음은 `강의 mm:ss`. |

## 강의자료·녹음본으로 문제집 업데이트하기

새 강의 PDF나 강의 녹음 텍스트를 Claude에게 올리고 "문제집 업데이트해 줘"라고 요청하면, [`CLAUDE.md`](CLAUDE.md)의 출제 규칙(시험지 형식, 5지선다, 공정 통합형 문항, 문항별 PDF 출처, 미출제 요소 반영)에 따라 새 문항 파일을 만들고 `index.json`과 `docs/coverage.md`를 함께 갱신합니다. 녹음 텍스트가 있으면 출처에 `강의 mm:ss`가 함께 붙습니다.

## 폴더 구조

```
index.html              앱 화면(진입점)
css/style.css           스타일(모바일 우선·다크 모드·인쇄용 시험지)
js/app.js               앱 로직(출제·채점·오답 노트·기록)
questions/index.json    불러올 문제 파일 목록
questions/*.json        단원별 문제
tools/validate_questions.py  문제 파일 형식 검사기
docs/coverage.md        단원별 출제/미출제 현황
CLAUDE.md               출제 규칙(문제집 업데이트용)
```
